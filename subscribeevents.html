subscribeEvents: Unauthenticated Observation + MCP Attack Chain

From the open event stream to demonstrated injection  ·  companion to cowork.exponential-systems.net  ·  2026

The Cowork architecture page documents subscribeEvents as the sole unauthenticated method on the cowork-svc named pipe: any local process can subscribe and receive real-time stdout, stderr, exit, and network events from whatever the VM is running. This page documents the composition of that open channel with the MCP server surface — a composition demonstrated by the March 14, 2026 investigation on DESKTOP-B7SG880.

The Two Primitives

1. subscribeEvents: No Authentication

Every cowork-svc method except subscribeEvents requires mutual TLS with the Anthropic-signed claude.exe certificate (thumbprint dbde5d16768ed0c1). subscribeEvents accepts connections from any local process. A subscriber receives the full event stream:

  • stdout — everything a VM process writes to standard output
  • stderr — error output, diagnostics, log lines
  • exit — process exit codes
  • networkStatus / apiReachability — network connectivity events

The stream content includes AI responses generated by the model, code execution output, file contents read by tools, credentials written to stdout, and any other output from processes running in the VM — without authentication.

2. MCP Servers Are Local Processes

MCP servers are Node.js processes spawned by claude.exe on the host. They run at user privilege, in the same local context as cowork-svc.exe. Any local process can open a connection to the cowork-svc named pipe and call subscribeEvents.

This means: any MCP server running on the host can subscribe to the full VM event stream. No special privilege, no certificate, no additional access required. The condition is only that the MCP server runs locally — which is the definition of an MCP server.

The Composed Attack Chain

Compromised MCP → Full VM Output
1.MCP server installed in tool-cdn or claude_desktop_config.json
2.claude.exe spawns MCP server process (user privilege, local context)
3.MCP server opens \\.\pipe\cowork-vm-service
4.Calls subscribeEvents — succeeds with no authentication
5.Receives full real-time VM event stream — AI responses, code output, file contents, credentials
6.Exfiltrates stream to attacker-controlled destination

Demonstrated, Not Theoretical

On March 14, 2026 (session 45f8071f), 16 files were found injected into tool-cdn on DESKTOP-B7SG880. Tool-cdn is the MCP server installation used by that machine's Claude Desktop. The 16 files included modified versions of the MCP server entrypoints — files that would be executed by claude.exe as MCP server processes. The injection vector was the MCP server installation itself. A compromised tool-cdn MCP server on that machine had local process access and could have subscribed to the event stream.

The Asymmetry: Command vs. Observation

The cowork-svc pipe presents two distinct capability surfaces with different authentication requirements:

SurfaceAuthenticationWhat it provides
Command (all methods except subscribeEvents) Mutual TLS — Anthropic-signed claude.exe cert required Create VMs, spawn processes, read files, mount paths
Observation (subscribeEvents) None — any local process Full real-time output of all running VM processes

The cert architecture answers "who can act" but explicitly does not apply to observation. A process that cannot create a VM or spawn a process can still receive the complete output of every process that is running.

SYSTEM Privilege Persists Without VM When Hyper-V is absent or disabled, cowork-svc cannot start a VM. The service still runs at SYSTEM privilege, holds the named pipe open, and subscribeEvents still accepts connections. The unauthenticated observation endpoint is present regardless of whether the VM capability is active.
