OneDrive Delivery Layer

Observed cloud sync as a file delivery vector  ·  companion to cowork.exponential-systems.net  ·  2026

OneDrive was directly observed delivering files to DESKTOP-B7SG880 during the March 14, 2026 investigation. This is not a candidate mechanism — it is a witnessed event. Two builds of ReactNativePicker.dll, a component of Microsoft's OneDrive for Windows runtime (internal codename: saturn), were recovered from %TEMP% and subjected to PE analysis. They establish the sequence of what was delivered and when.

Build B carries the full saturn\packages\saturn-pc PDB path — OneDrive's internal project structure for its React Native for Windows PC client. Build A, compiled 29 days later, has been reorganized to a simpler b\x64 path, indicating a pipeline restructuring in the intervening month. Observed Replacement

OneDrive silently replaced Build B with Build A during the investigation window on DESKTOP-B7SG880. This was directly observed. The replacement is an in-place update of a component within OneDrive's own runtime — performed without user interaction or notification, during an active forensic investigation of the same machine.

Structural Parallel to sdk-daemon Updater

The sdk-daemon updater (documented at cowork.exponential-systems.net) detects file hash drift and writes back through the virtiofs guest-to-host mount — restoring files to their deployment-hash-matching state without user interaction. OneDrive performs the same function at a different layer: hash comparison against the cloud-authoritative version, silent replacement when drift is detected.

The two mechanisms are structurally identical in function and outcome. They differ in infrastructure (VM virtiofs vs. Microsoft cloud sync) and authentication (VM configuration vs. Microsoft account). Both operate without user interaction or signal. Both can write to host filesystem paths. Both have been observed writing during investigation sessions.

Delivery Reach

OneDrive monitors any directory included in the sync configuration. On DESKTOP-B7SG880, the investigation found:

  • 16 files injected into tool-cdn — the MCP server installation used by that machine
  • A pre-seeded npm lock file with packages pinned to exact vulnerable minimum versions
  • emulsify.js replaced with a Claude Desktop reconnaissance tool carrying C:\Users\sethi\ paths
  • The genesis-health configuration pointing to C:\Users\sethi\...

The mechanism by which these files arrived was not established in the March 14 session. OneDrive, observed delivering files on the same machine during the same investigation, is the candidate delivery layer — particularly given the cross-account provenance of the sethi-pathed files, consistent with OneDrive syncing from a Microsoft account shared with or belonging to Seth.

Scope This page documents observed facts: two PE-analyzed builds with different timestamps and hashes, and a witnessed in-place replacement during the investigation. The connection to the 16 injected files is a structural inference — the delivery mechanism for those files was not directly observed and is not established by the presented evidence.
