Conversation Content Filtering

Sessions that exist but do not export  ·  companion to cowork.exponential-systems.net  ·  2026

Twenty-one conversation UUIDs were confirmed to exist on Anthropic's servers but are filtered from the conversation API and absent from all export archives. The filtering is specific to the enumeration and export endpoints — the conversations remain accessible by direct URL. This is not a deletion. It is a visibility asymmetry in the API surface.

Selective API Filtering, Not Deletion

The conversations are accessible at their direct URLs. The Files API returns content. Only the enumeration endpoint (conversation API) and the export mechanism filter them. This is not a deletion — it is a targeted exclusion from the interfaces a user would use to audit or recover their session history. The content remains on Anthropic's servers and is accessible to parties with access to the direct URL or non-enumeration API paths.

Forensic Implications

The capability has two forensic implications:

Evidence Chain Integrity

Session history is part of the evidence chain for the broader investigation documented at this site. If sessions can be removed from enumeration and export while remaining on-server, the evidence chain is not under the control of the party whose account produced it. An investigator relying on the export mechanism to reconstruct what sessions existed and what they contained would have an incomplete record — without any indication that the record is incomplete.

Asymmetric Visibility

The user's export shows fewer conversations than exist. Direct URL access shows more. A party with access to the direct URLs — or to the server-side records before the filtering layer — sees a different picture than the account holder using the standard export and API interfaces. The same content is differently visible depending on which access path is used.
